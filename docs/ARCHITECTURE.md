# Architecture Reference — Commercial Server-Grade DDR4 Memory Controller

## 1. Project Overview

This project implements a **commercial server-grade DDR4 SDRAM memory controller** targeting JEDEC JESD79-4B. The design is fully synthesizable RTL (Verilog-2012) and is intended for use in FPGA prototyping and ASIC tapeout flows.

### Key capabilities

| Feature | Description |
|---|---|
| JEDEC standard | DDR4 SDRAM — JESD79-4B |
| Host interface | AXI4 (64-bit data, 32-bit address) |
| DRAM bus width | 64-bit data + 8-bit ECC = 72-bit total |
| ECC | SECDED (72,64) — single error correct, double error detect |
| Ranks | 1–4 configurable ranks |
| Refresh | Auto-refresh (REF command), configurable tREFI / tRFC |
| Timing parameters | All critical JEDEC timing registers are software-programmable |
| Burst length | BL8 (fixed burst length 8, as per DDR4 spec) |
| Clock | Single-ended `clk` input; DDR4 differential pair generated by PHY |
| Reset | Active-low synchronous `rst_n` |

## 4. Timing, Protocols, and Constraints

### 4.1 JEDEC DDR4 timing parameters (JESD79-4B)

All timing registers are software-configurable at boot via the `cfg_timing_*` interface.
Reset defaults target **DDR4-3200 (1600 MHz data rate)** with a **2:1 half-rate controller clock of 800 MHz**.

| Parameter | Symbol | DDR4-3200 Default (tCK) | Register Offset | Description |
|---|---|---|---|---|
| CAS Latency | CL | 22 | 0x00 | Read latency: column command to first valid data |
| CAS Write Latency | CWL | 16 | 0x04 | Write latency: column command to DQ write |
| Row to Column Delay | tRCD | 22 | 0x08 | ACT to RD/WR minimum |
| Row Precharge | tRP | 22 | 0x0C | PRE to next ACT minimum |
| Row Active Strobe | tRAS | 52 | 0x10 | ACT to PRE minimum |
| Row Cycle | tRC | 74 | 0x14 | ACT to ACT (same bank) |
| Refresh Interval | tREFI | 6240 | 0x18 | Average refresh interval (7.8 us at 800 MHz half-rate) |
| Refresh Cycle (1x) | tRFC1 | 560 | 0x1C | REF to next valid command (16 Gb density) |
| Refresh Cycle (2x) | tRFC2 | 320 | 0x20 | Fast refresh mode |
| Write Recovery | tWR | 24 | 0x24 | Last write to PRE |
| Write-to-Read (short) | tWTR_S | 4 | 0x28 | Write to read, different bank group |
| Write-to-Read (long) | tWTR_L | 12 | 0x2C | Write to read, same bank group |
| Read-to-Precharge | tRTP | 12 | 0x30 | RD to PRE minimum |
| CAS-to-CAS (short) | tCCD_S | 4 | 0x34 | CAS to CAS, different bank group |
| CAS-to-CAS (long) | tCCD_L | 6 | 0x38 | CAS to CAS, same bank group |
| RAS-to-RAS (short) | tRRD_S | 4 | 0x3C | ACT to ACT, different bank group |
| RAS-to-RAS (long) | tRRD_L | 6 | 0x40 | ACT to ACT, same bank group |
| Four Activate Window | tFAW | 32 | 0x44 | Max 4 ACTs within tFAW window (same rank) |
| ACT-to-ACT diff LR | tRRD_DLR | 8 | 0x48 | ACT to ACT, different logical rank (3DS stacked DRAM) |

### 4.3 ECC scheme — SECDED (72, 64)

The ECC engine implements the standard Hamming-based SECDED code over a 64-bit data word
with 8 check bits (7 Hamming parity bits + 1 overall parity bit).

- **Encode (write path)**: 64-bit data in -> 72-bit codeword out (appends 8 check bits)
- **Decode (read path)**: 72-bit codeword in -> 7-bit syndrome -> single-bit correction or double-bit error flag
- **Syndrome = 0**: no error
- **Syndrome != 0, overall parity wrong**: single-bit error, correctable; corrected data forwarded to host
- **Syndrome != 0, overall parity correct**: double-bit error, uncorrectable; SLVERR returned on AXI
- **Error reporting**: `ecc_sb_err` and `ecc_db_err` are sticky outputs; `ecc_err_addr` latches the first
  faulting address; cleared by writing 1 to bits [1:0] of `ECC_ERR_CLR` register
- **Granularity**: ECC operates on 64-bit (8-byte) words; sub-word byte-masked writes trigger an internal
  read-modify-write (RMW) cycle to maintain ECC integrity

### 4.4 Refresh strategy

The `refresh_fsm` implements a **distributed auto-refresh** scheme:

1. A `tREFI` down-counter fires a refresh request every 7.8 us (per JEDEC DDR4 spec).
2. Refresh requests have higher priority than normal commands; the `cmd_scheduler` is stalled.
3. If any banks are open, the refresh FSM signals the timing FSM to precharge all open banks before issuing REF.
4. The controller holds off new commands for `tRFC1` (or `tRFC2` in fast-refresh mode) after REF.
5. Up to 8 refresh commands may be deferred (per JEDEC allowance); a 4-bit credit counter tracks deferred refreshes.
6. If the credit counter saturates (8 deferred), the refresh FSM forces an immediate refresh regardless of open transactions.

### 4.5 Initialization sequence (init_fsm FSM)

```
RESET_ASSERT  --> RESET_DEASSERT --> CKE_LOW_WAIT -->
CKE_ASSERT --> MRS_MR3 --> MRS_MR6 --> MRS_MR5 --> MRS_MR4 -->
MRS_MR2 --> MRS_MR1 --> MRS_MR0 --> ZQCL --> INIT_DONE
```

Each state waits the required JEDEC timing (tXPR, tMRD, tMOD, tZQINIT) before advancing.
`init_done` is asserted after the ZQCL is complete; the `cmd_scheduler` is held in reset until then.

### 4.6 Clock domains and reset

| Domain | Frequency | Description |
|---|---|---|
| `clk` | 800 MHz (half-rate) | Controller logic, AXI interface, scheduler, timing FSM |
| DDR4 CK (PHY-internal) | 1600 MHz | DDR4 bus clock; generated inside `phy_if` from `clk` x2 |
| `rst_n` | — | Active-low synchronous reset; de-asserted synchronously with `clk` |

All controller flip-flops use `clk` rising edge and `rst_n`.
The PHY handles its own DDR4-domain clock crossing internally.

## 6. Configuration Register Map

All registers are 32-bit wide, accessible via the `cfg_timing_*` APB-style interface.

| Offset | Register | Reset Value | Description |
|---|---|---|---|
| 0x00–0x5C | Timing registers | See §4.1 defaults | Per-parameter timing in tCK units (see §4.1) |
| 0x60 | `CTRL_STATUS` | 0x00000000 | [0] init_done; [1] refresh_busy; [2] ecc_sb_err (sticky); [3] ecc_db_err (sticky) |
| 0x64 | `ECC_ERR_ADDR` | 0x00000000 | Address of most recent ECC error (latched on first error) |
| 0x68 | `ECC_ERR_CLR` | 0x00000000 | Write [0]=1 to clear ecc_sb_err sticky bit; Write [1]=1 to clear ecc_db_err sticky bit |

| 0x70 | `RANK_CFG` | 0x00000000 | [1:0] number of active ranks minus 1 (matches cfg_ranks port) |
| 0x74 | `ZQCAL_CTRL` | 0x00000000 | [0] periodic ZQCS enable; [15:1] ZQCS interval in units of tREFI |

## 7. Address Mapping

The controller decodes a flat 32-bit AXI address into DDR4 row/column/bank/bank-group/rank.
Default mapping for x8 DRAM components with BL8 and a 64-bit host bus:

```
AXI addr[31:0]:
  [2:0]   -> ignored (always 0; 64-bit AXI is naturally 8-byte aligned)
  [8:3]   -> column[5:0]   (column address bits within an open row)
  [10:9]  -> bank[1:0]
  [12:11] -> bank_group[1:0]
  [13]    -> rank[0]        (present only when cfg_ranks > 0)
  [30:14] -> row[16:0]
  [31]    -> rank[1]        (present only when cfg_ranks > 2)
```

## 8. Notes and External References

1. **JEDEC standard**: JESD79-4B — *DDR4 SDRAM Standard*, JEDEC Solid State Technology
   Association, 2020. All timing symbols and mode register definitions follow this document.
2. **ECC code**: The SECDED (72,64) scheme matches the industry-standard IBM implementation
   used in LRDIMM and RDIMM server modules. Check bits use the standard Hamming distance-4 code.
3. **PHY abstraction**: `phy_if` is a behavioral model of the DDR4 PHY. In a real ASIC flow,
   replace with a vendor PHY hard macro (e.g. Synopsys DWC_ddr4phy, Cadence DDR4 PHY).
   For Xilinx UltraScale+ FPGAs, use the MIG DDR4 PHY IP.
4. **Synthesis target**: Controller core targets 800 MHz at 7 nm ASIC.
   For Xilinx UltraScale+, the practical limit is approximately 400 MHz; use a 400 MHz
   half-rate controller clock with 800 MHz DDR4 data rate in that case.
5. **Reset policy**: `rst_n` is synchronous to `clk`. An external power-on-reset (POR) circuit
   must hold `rst_n` low for at least 200 us to satisfy DDR4 RESET# requirements;
   this is handled outside the controller RTL.
6. **Backpressure**: The AXI4 interface deasserts `awready`/`arready` when the command queue
   is full. No transactions are lost or corrupted.
7. **Burst support**: Only AXI4 INCR bursts of length 1 (single 64-bit beat) and length 8
   (BL8 = 512-bit cache line fill) are supported. WRAP bursts are not supported.
8. **Read-modify-write**: Sub-word byte-masked writes trigger an internal RMW so the ECC check
   bits remain consistent with all 64 data bits in the DRAM row.
